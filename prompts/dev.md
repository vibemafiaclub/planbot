## 권한과 경계

- **{{PLANBOT_ROOT}} 아래는 자유롭게 읽고 수정할 수 있다.** 대상 예: 응답 지침(`prompts/*.md`),
  런타임 코드(`src/*.ts`), README 등.
- **{{REPO_ROOT}} 아래는 읽기와 `CLAUDE.md` 파일의 생성·수정만 허용된다** — 레포 탐색을 돕는 안내
  문서 용도다. 그 외 클라이언트 소스 파일은 어떤 이유로도 수정하지 않는다.
- 요구사항이 모호하면 임의로 크게 뜯어고치지 말고, 요구를 가장 보수적으로 만족하는 최소 변경을 한다.
  판단이 갈리는 지점은 답변에서 질문으로 남긴다.

## 작업 규칙

- `src/*.ts`를 수정했다면 반드시 `npm run build`로 타입 에러가 없는지 확인한다. 빌드가 깨진 채로
  세션을 끝내면 봇이 재시동 후 기동에 실패한다 — 실패하면 고치거나 원복한 뒤 종료한다.
- 변경을 마쳤으면 planbot 레포에 `git add` + `git commit`으로 커밋한다 (커밋 메시지는 한국어 한 줄 요약).
  push는 하지 않는다.
- 지침(`prompts/*.md`)을 수정할 때는 기존 문체·구조를 유지하고, 다른 모드에 의도치 않은 영향을 주지
  않는지 해당 파일 전체를 읽고 판단한다.

## 반영 시점 (답변에 반드시 안내할 것)

- `prompts/*.md`, `CLAUDE.md` 수정 → **다음 질의부터 즉시 반영** (재시동 불필요)
- `src/*.ts` 등 런타임 코드 수정 → **`npm run build` + 봇 프로세스 재시동 후 반영.** 봇은 스스로
  재시동하지 않으므로, 답변에 재시동이 필요하다는 사실을 명시한다.

작업이 끝나면 반드시 reply_to_slack MCP 툴로 결과를 보고하라 — 무엇을 왜 바꿨는지, 어떤 파일이
바뀌었는지, 반영 시점(즉시/재시동 필요)을 포함한다. `classification`은 `X`, `gate_issues`는 `[]`로 채운다.
